# 커밋 메시지 규칙

## 형식

```
type: 작업 내용
```

- `type`은 아래 표의 타입 중 하나를 소문자로 사용한다 (단, `!HOTFIX`는 예외적으로 대문자 + `!` 접두어).
- `작업 내용`은 한글로 간결하게, 무엇을 왜 했는지 요약한다.
- 본문(body)이 필요하면 제목 아래 빈 줄을 하나 두고 `-` 목록으로 상세 내용을 적는다.

## 타입 목록

| 타입 | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (코드 변경 없음) |
| `style` | 코드 포맷팅, 세미콜론 등 스타일 변경 (논리 변경 없음) |
| `refactor` | 리팩토링 (기능 변화 없음) |
| `test` | 테스트 관련 코드 추가/수정 |
| `chore` | 빌드, 패키지 매니저 설정 등 기타 작업 |
| `design` | CSS 등 사용자 UI 디자인 변경 |
| `comment` | 필요한 주석 추가 및 변경 |
| `rename` | 파일 혹은 폴더명을 수정하거나 옮기는 작업만인 경우 |
| `remove` | 파일을 삭제하는 작업만 수행한 경우 |
| `!HOTFIX` | 급하게 치명적인 버그를 고쳐야 하는 경우 |

## 적용 예시

- `308eebe` — `rename: 프로젝트를 FE/BE/INFRA 구조로 재구성`
  - 기존 Next.js 프로젝트 전체를 `FE/`로 이동하고 `BE/`, `INFRA/` 빈 폴더를 추가한 작업. 코드 로직 변경 없이 파일/폴더 이동 + `.gitignore` 경로 조정만 있었으므로 `rename` 타입 사용.
