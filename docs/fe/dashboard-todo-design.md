# 주요 정보: 개인화 할 일 화면 설계

작성 2026-09-10 · 브랜치 `FE/fix/shell-responsive-and-spacing` · 기준 `dev@db925e0`

관련 — 디자인 시스템 `FE/DESIGN.md` · 권한 모델 `FE/data/roles.ts` · 자격 조회 `FE/lib/workspace-api.ts`

이 문서는 **구조 확정용**이다. 색·컴포넌트·간격은 여기서 정하지 않는다 —
구조와 섹션 내용이 정해진 뒤 `FE/DESIGN.md` 범위 안에서 UI를 얹는다.

---

## 1. 무엇을 바꾸는가

지금 `/dashboard`(주요 정보)는 **지표 대시보드**다 — 현금흐름 예측 · 납기 준수율 ·
실시간 가동 현황이 맨 위에 있고, 그 아래 KPI 위젯이 깔린다. 모든 사람에게 같은 화면이다.

바꾸려는 것은 **개인화된 할 일 화면**이다.

- 할 일은 **각 기능 안에서** 생긴다. 주요 정보가 기능을 뒤져 만드는 것이 아니다.
- 주요 정보는 그중 **내 권한과 내 범위에 걸리는 것만** 받아 세운다.
- 그래서 이 화면은 부서 대시보드가 아니라 **사람마다 다른 화면**이다.

지표는 없애지 않는다. 순서를 내린다 — 지표는 *봐 두는 것*이고 할 일은 *처리하는 것*이며,
`scope`가 `own`인 사람에게는 지표 대부분이 애초에 볼 권한이 없는 값이다.

## 2. 흐름

```
[1 발생]  기능이 자기 할 일을 내놓는다
          어느 탭 소관(featureId) · 누구 것(ownerId) · 어느 부서(deptId)를 달아서
             ↓
[2 관문]  내 권한 · 내 범위로 거른다      ← 개인화가 일어나는 유일한 지점
          me.modules ∩ me.permissions ∩ scope
             ↓
[3 표시]  주요 정보에 선다
          누르면 그 할 일이 난 자리로 바로 간다
```

1·2단계와 데이터 계약은 어떤 화면 구조를 고르든 같다. 구조 선택은 3단계에만 영향을 준다.

---

## 3. 개인화에 쓰는 값 — 이미 있다

`GET /api/workspace/me` (`WorkspaceMeDto`, `FE/lib/workspace-api.ts`)가 전부 준다.

| 값 | 쓰임 |
| --- | --- |
| `modules: string[]` | 내가 쓸 수 있는 모듈 slug (회사가 켠 것 ∩ 직급·개인 권한) — 1차 필터 |
| `permissions.perms` | 내 직급의 서브기능(탭) 권한 — 2차 필터 |
| `permissions.scope` | `all` / `dept` / `own` — 범위 필터 |
| `permissions.showAmounts` | 금액 열을 볼 수 있는지 |
| `member.departmentId` · `departmentName` | `dept` 범위 판정 · 화면 머리 표기 |
| `member.roleName` | 화면 머리 표기 |

**새로 만들 것은 할 일 한 건의 모양 하나뿐이다.**

## 4. 데이터 계약

```ts
type TodoItem = {
  id:         string   // "INV-RCV-0031"
  module:     string   // "inventory"   — me.modules 로 1차 판정
  featureId:  string   // "receiving"   — permissions 로 2차 판정 (탭 단위)
  severity:   "urgent" | "warn" | "normal"
  title:      string   // "입고 대기 3건"
  detail?:    string   // "부분 입고 2 · 미입고 1"
  due?:       string   // "2026-09-12"  — 마감 섹션 / C안의 축
  ownerId?:   number   // scope:own 판정
  deptId?:    number   // scope:dept 판정
  createdBy?: number   // 「기다리는 일」 판정
  state?:     string   // "검토중" — 상태 배지
  amount?:    number   // showAmounts 가 아니면 그리지 않는다
  href:       string   // "/modules/inventory?tab=receiving"
}
```

관문은 이 순서로 자른다.

1. `me.modules.includes(t.module)`
2. `me.permissions.perms.includes(t.featureId)`
3. `scope === "all"` → 통과 / `"dept"` → `t.deptId === me.departmentId` / `"own"` → `t.ownerId === me.id`
4. `!me.permissions.showAmounts` → `t.amount`를 지운다

### 1차 데이터 출처

모듈마다 이미 `stats: StatData[]`가 있고 그 안에 `cta: { label, tabId }`(바로 갈 곳) ·
`deltaTone`(심각도) · `dday`(마감)가 들어 있다(`FE/data/pages/*.ts`).
1차는 **`stats` → `TodoItem` 변환기 하나**로 시작할 수 있다 — 모듈 코드를 건드리지 않는다.
BE가 건별 데이터를 주기 시작하면 같은 계약을 채우면 되고 화면은 다시 고치지 않는다.

지금 더미 데이터에서 나오는 할 일(참고):

| 기능 | 할 일 | 심각도 |
| --- | --- | --- |
| 경영지원 | 급여 처리 대기 1 · 전표 검토 대기 1 | 주의 (`pendingCounts`로 실시간 계산) |
| 제품설계 | 미매핑 BOM 2 · 확인 필요 파생 도면 1 · 정제 엑셀 미첨부 1 | 긴급 / 주의 |
| 생산관리 | 진행 중 작업지시 9 | 보통 |
| 장비관리 | 고장 위험 경고 2 · 이번 주 정비 4 | 긴급 / 보통 |
| 품질검사 | 진행 중 시정조치(CAPA) 3 | 보통 |
| 재고·물류 | 입고 대기 3 · 진행 중 발주 5 · 미입고 잔량 17 EA | 주의 / 보통 |
| 영업관리 | 진행 중 수주 17 | 보통 |
| 고객지원 | 미처리 AS 티켓 6 | 주의 |

**기한(`dday`)은 8개 모듈 통틀어 0건이다.** 시간축 구조(C안)를 고르려면 먼저 붙여야 한다.

## 5. 화면 구조 3안

재료는 같고 배치가 다르다. 안을 바꿔도 데이터 계약은 그대로다.

### A안 — 섹션 스택 (권장, 지금 데이터 기준)

역할이 다른 덩어리를 위에서 아래로 쌓는다. 처리와 조망을 한 화면에서 한다.

```
┌ 1 화면 머리 — 「주요 정보」 · {부서} {직급} · {범위} 기준 · 처리할 일 N건 ┐
├──────────────────────────────┬───────────────────────────┤
│ 2 지금 처리할 일 (급한 순 7줄)   │ 4 오늘 · 이번 주 마감        │
│ 3 내가 올려둔 일 (남을 기다림)   │ 5 내 기능 바로가기           │
├──────────────────────────────┴───────────────────────────┤
│ 6 기능별 대기 현황 — 내가 쓸 수 있는 기능만 (8칸 고정 아님)      │
├──────────────────────────────────────────────────────────┤
│ 7 부서 · 전사 지표 — scope ≥ dept 인 사람만                  │
└──────────────────────────────────────────────────────────┘
```

- 강점 — 처리와 조망이 한 화면. 권한이 좁으면 섹션이 자동으로 줄어 화면이 짧아진다.
- 약점 — 할 일이 20건을 넘으면 「7줄 + 더 보기」가 매일 걸린다. 세로가 길다.
- 맞는 사람 — 여러 기능을 얕게 걸치는 관리자·팀장.

### B안 — 인박스 (목록 + 미리보기)

메일함처럼 왼쪽에 한 줄씩 쌓고, 고르면 오른쪽에 그 건과 처리 버튼이 뜬다.
경영지원 작업대(마스터 → 디테일)와 **같은 문법**이라 새로 배울 것이 없다.

```
┌ 머리 + 필터 칩 [전체 12] [긴급 2] [마감 3] [내가 올린 것 2] [기능별 ▾] ┐
├─────────────────────────┬──────────────────────────────┤
│ 할 일 목록 (개수 제한 없음)  │ 고른 할 일 — 미리보기            │
│ · 한 줄 = 심각도·제목·시각   │ 무엇 / 왜 / 관련 값 2~3          │
│ · 스크롤                  │ [기능에서 열기] [다음 건]         │
├─────────────────────────┴──────────────────────────────┤
│ 내 기능 바로가기 (한 줄 띠) — 지표는 이 화면에 없다              │
└────────────────────────────────────────────────────────┘
```

- 강점 — 건수가 늘어도 그대로 쓴다. 한 건 처리 → 다음 건 흐름이 가장 빠르다.
- 약점 — 전체 지형과 지표가 사라진다. 할 일 0건이면 화면이 텅 빈다.
- 맞는 사람 — 같은 종류의 일을 많이 처리하는 실무자(입고 검수·전표 승인).

### C안 — 하루 브리핑 (시간축)

심각도가 아니라 **시간**으로 세운다. 밀린 것이 맨 위.

```
┌ 오늘 한 줄 — 9월 10일 · {부서} {직급} · 밀림 1 · 오늘 2 · 이번 주 3 ┐
│  밀림     │ [2일 지남] ...                                    │
│  오늘     │ [D-0] ... [D-0] ...                              │
│  이번 주  │ [D-2] ... [D-4] ... [D-6] ...                    │
│  기한 없음 │ 긴급/주의 순 — 지금 데이터는 대부분 여기로 온다        │
├─────────────────────────────────────────────────────────┤
│ 내 기능 바로가기 + 지표(권한 있을 때)                          │
└─────────────────────────────────────────────────────────┘
```

- 강점 — 「밀린 것」이 맨 위라 놓친 일이 드러난다. 마감이 일을 끄는 업무에 가장 강하다.
- 약점 — **지금 데이터에 기한이 0건**이라 붙이기 전에는 거의 전부 「기한 없음」에 쌓인다.
- 맞는 사람 — 급여·발주·정비처럼 날짜가 일을 끄는 담당자.

### 재료가 어디로 가는가

| 재료 | A안 | B안 | C안 |
| --- | --- | --- | --- |
| 내가 누구로 보는가 | 머리 부제 | 머리 부제 | 「오늘 한 줄」 |
| 지금 처리할 일 | 전용 섹션 7줄 | 목록 전체 | 시간 구간에 흩어짐 |
| 기다리는 일 | 전용 섹션 | 필터 「내가 올린 것」 | 시간 구간에 섞임 |
| 마감 | 전용 섹션 | 필터 「마감」 | **화면의 축** |
| 기능별 대기 | 8칸 보드 | 필터 드롭다운 | 하단 띠 |
| 바로가기 | 우측 카드 | 하단 띠 | 하단 띠 |
| 지표 | 맨 아래 | **없음** | 하단 띠 |
| 한 건 상세 | 기능 화면으로 | **우측 미리보기** 후 이동 | 기능 화면으로 |

**고를 때 실제로 갈리는 것** — 하루에 할 일이 몇 건 생기는가(5~10건이면 A, 30건 넘으면 B),
그 일에 날짜가 붙는가(붙으면 C). 지금 더미 기준 8~12건 · 기한 0건이라 A안이 안전하고,
B안은 운영 건수가 늘었을 때의 다음 단계로 둔다.

## 6. 섹션 명세 (A안 기준)

B·C안을 고르면 5절 표의 자리로 그대로 옮긴다.

| 자리 | 목적 | 내용 · 정렬 | 권한 · 범위 | 없을 때 |
| --- | --- | --- | --- | --- |
| 1 화면 머리 | 이 화면이 「내 화면」임을 알린다 | 「주요 정보」 + 부제 `{부서} {직급} · {범위} 기준 · 처리할 일 N건` | `departmentName` · `roleName` · `scope` | 부서 없음 → 「{직급} · 내 담당 기준」 |
| 2 지금 처리할 일 | 지금 손대야 하는 것 | 긴급 → 주의 → 마감 임박, 같으면 오래된 것 먼저. 7줄 + 「더 보기」. 한 줄 = 심각도·제목·기능명·바로가기 | `modules` ∩ `perms` ∩ `scope` | 「처리할 일이 없어요」 + 자주 여는 기능 3개 |
| 3 기다리는 일 | 내 손을 떠났지만 안 끝난 것 | 내가 만든 전표·발주·요청 중 남의 결재 대기. 오래된 순. 상태 배지 + 대기 일수. **여기서는 조치하지 않는다** | `createdBy = 나` (범위 무관) | 섹션째 감춘다 |
| 4 마감 | 날짜에 걸린 것 | `due` 있는 것만. 오늘 → 이번 주. D-표기. 2번과 겹치면 2번에서 뺀다 | 2번과 동일 | 섹션째 감춘다 |
| 5 바로가기 | 할 일이 없어도 들어갈 입구 | 내가 쓸 수 있는 기능 + 대기 건수 배지. 최근 연 순 | `me.modules` | 기능 0 → 「관리자에게 권한을 요청해 주세요」 |
| 6 기능별 대기 | 전체 지형을 한눈에 | 기능 한 칸 = 대기 상위 3줄. 칸 수는 사람마다 다르다 | `me.modules` · 각 줄은 `perms` | 칸이 없으면 섹션째 감춘다 |
| 7 지표 | 추세를 봐 둔다 | 현금흐름 · 납기 준수율 · 가동 현황. 금액은 `showAmounts`일 때만 | `scope ≥ dept` | 권한 없으면 섹션째 감춘다 (잠금 표시도 두지 않는다) |

빈 상태는 `EmptyState`를 쓰고 UX 라이팅은 해요체를 따른다(`FE/DESIGN.md`).

## 8. 열린 결정

1. **구조** — A / B / C. 지금 데이터 기준 권장은 A안.
2. **`scope: own` 판정** — 할 일마다 담당자가 있어야 성립하는데 지금 데이터에는 팀장(`head`)만 있고
   건별 담당자가 없다. ① 건별 `ownerId` 신설 ② 부서 귀속으로 대체(`own`을 `dept`처럼) ③ 우선 「내가 만든 것」만.
3. **1차 데이터 출처** — 기존 `stats` 변환기로 시작할지, BE 계약(`GET /api/todos`)을 먼저 정할지.
4. **AI알림과의 경계** — `/ai-diagnosis`는 AI가 *감지한* 이상, 주요 정보는 사람이 *처리할* 대기 건이다.
   겹치는 항목(고장 위험 경고)은 주요 정보에서 한 줄로 요약하고 상세는 AI알림으로 보낸다.

## 9. 함께 정리된 것 (이 브랜치에서 이미 반영)

- 페이지 아우터의 폭 제한(`mx-auto max-w-7xl`)을 없앴다. 화면마다 캡이 달라 제목 왼쪽 x가
  272 ↔ 512로 튀던 것을 없애고, 남는 폭은 여백이 아니라 열 수로 쓴다. AI대화는 예외(자체 셸).
- 경영지원 헤더의 부제(「처리를 기다리는 일 N건 — 급여 n · 회계 n」)를 뺐다.
  대기 건수는 이 문서의 주요 정보 화면이 지는 역할이고, 모듈 헤더에서 두 번 말하지 않는다.
